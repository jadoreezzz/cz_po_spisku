# Telegram-бот сборки PDF с ЧЗ-метками

Присылаете боту свои PDF-этикетки ЧЗ и список артикулов — получаете один PDF
для печати: страницы в том же порядке и с теми же повторами, что и список.

Бот **не создаёт** коды ЧЗ. Он только переупорядочивает страницы уже существующих
этикеток. Присланные файлы не изменяются.

## Локальный запуск (на этом Mac)

1. Создать бота в @BotFather, получить токен.
2. Положить токен: `echo '123456:AA...' > ~/.cz_bot_token && chmod 600 ~/.cz_bot_token`
3. Узнать свой Telegram ID: запустить бота, написать ему `/whoami`.
4. Разрешить себе доступ: `echo '<ваш id>' > ~/.cz_bot_allowed_users` и перезапустить бота.
   Пока список пуст, бот отвечает только инструкцией и ничего не собирает —
   иначе любой, кто узнает адрес бота, получил бы доступ к папкам на этом Mac.
5. Запуск: `./run_bot.sh`

Пулы этикеток бот хранит в `~/.cz_bot_pools/<chat_id>/`. Запасной режим чтения
папок с диска смотрит в `~/Desktop`; другое расположение — `CZ_LABEL_ROOTS`
(пути через `:`).

## Деплой на Railway (бот работает без вашего компьютера)

1. Создать проект в Railway из этого GitHub-репозитория (Deploy from GitHub repo).
2. Переменные окружения в настройках сервиса:

   | переменная | значение |
   |---|---|
   | `CZ_BOT_TOKEN` | токен от BotFather |
   | `CZ_BOT_ALLOWED_USERS` | ваш Telegram ID (узнать: `/whoami`), несколько — через запятую |
   | `CZ_POOL_ROOT` | `/data/pools` |

3. **Подключить том (Volume)** и примонтировать его в `/data`. Без тома файловая
   система Railway обнуляется при каждом деплое — сохранённые пулы пропадут.
4. Деплой. Логи должны заканчиваться строкой `Бот запущен. Хранилище пулов: /data/pools`.

Сервис должен быть **в одном экземпляре**: Telegram не отдаёт обновления двум
процессам сразу (`numReplicas: 1` уже прописан в `railway.json`). По той же причине
не держите одновременно запущенным локального бота и задеплоенного — они будут
перебивать друг друга.

Распаковщики `.rar` / `.7z` ставятся при сборке (`nixpacks.toml`, пакет
`libarchive-tools` + `p7zip-full` + `unar`), так что на сервере архивы работают
так же, как на Маке.

Папочный режим на сервере недоступен (там нет вашего Рабочего стола) — и не нужен:
этикетки приезжают в чат.

### Автозапуск на Маке (launchd)

`launchd/com.cz.pdfbot.plist` — шаблон. Установить:

```bash
cp launchd/com.cz.pdfbot.plist ~/Library/LaunchAgents/ && launchctl load ~/Library/LaunchAgents/com.cz.pdfbot.plist
```

Mac должен быть включён и в сети — бот работает только пока работает машина.
Вариант B (VPS + синхронизация папок) добавляет отказоустойчивость,
но требует канала синхронизации; начинать с него смысла нет, пока все файлы тут.

## Как это работает

1. Перетаскиваете боту свои PDF-этикетки ЧЗ — хоть 60 штук сразу, или архивом:
   `.zip`, `.rar`, `.7z`, `.tar`. RAR и 7z распаковываются системным `bsdtar`
   (есть в macOS из коробки); если попадётся архив, который он не осилит,
   поможет `brew install unar` — бот подхватит `unar`/`unrar`/`7z` автоматически.
2. Бот склеивает их в **пул** — единый PDF со всеми этикетками.
3. Присылаете список артикулов → получаете готовый PDF для печати:
   страницы в порядке списка, повтор в списке = ещё одна страница.

Быстрее всего — одним сообщением: прикрепить архив, а список написать
**в подписи к нему**. Тогда бот сразу вернёт готовые PDF на печать
(по одному на маркетплейс) — файл-пул в этом случае не присылается,
он просто сохраняется и доступен по `/pools`.

Если списка не было, бот пришлёт сам пул с пометкой, что это все этикетки,
а не файл на печать. Присланные боту PDF, собранные им же ранее
(`*_CZ_po_spisku.pdf`), в пул не попадают — иначе страницы задвоились бы.

Пул самодостаточен: индекс «страница → артикул» зашит внутрь самого PDF
(метаданные + закладки). Этикетки ЧЗ — картинки, текста в них нет, поэтому
просто склеенный PDF без индекса бесполезен: из него не понять, где какой артикул.
Сохранённый пул можно в следующий раз прислать вместо всех 60 файлов —
бот его узнает и сразу примет в работу.

Порядок не важен: можно сначала список, потом файлы — бот дождётся и соберёт сам
(через ~4 секунды после последнего файла; можно не ждать — `/go`).

Папки на диске не нужны. Если всё же указать в сообщении «папка BR 29» и пула нет,
бот возьмёт этикетки из папки на этом Маке — это запасной режим, не основной.

## Команды

* `/pools` — сохранённые пулы, `/pool <имя>` — переключиться, `/pool` — какой активен
* `/go [имя]` — собрать пул из уже присланных файлов, не дожидаясь паузы
* `/reset` — забыть накопленные файлы и незавершённые списки
* `/whoami` — ваш Telegram ID

## Формат списка

```
RUSH114B-XXL
RUSH083B-XXL

ozn

RUSH079B-L
V-SHORT001M-L

yand

папка BR 29
```

* маркеры Ozon: `ozon` / `озон` / `ozn`; Yandex: `yandex` / `яндекс` / `yand` / `ym`;
* маркер может стоять до или после своего списка, блоки в любом порядке;
* если список один — собирается только он;
* повторы и порядок строк сохраняются: N вхождений артикула = N страниц,
  даже если в файле этикетки страниц больше;
* «папка BR 29 и только она» — искать строго в этой папке;
* если папку не указали, бот спросит её отдельным сообщением;
* если под названием подходит несколько папок — бот перечислит их и переспросит,
  сам не угадывает.

### Список файлом Excel / CSV

Вместо текста можно прислать файл со списком — тот самый, который заполняет склад.
Формат не фиксирован, бот разбирается сам:

* ищет колонку с артикулами по заголовку (`Артикул`, `Ваш SKU`, `SKU`, `Артикул товара`…),
  а если заголовков нет — по содержимому (как в складском шаблоне, где просто
  столбик артикулов и рядом названия);
* **порядок строк = порядок страниц**, повторяющиеся строки дают столько же страниц;
* необязательная колонка `Количество` разворачивается в повторы: `2` = две страницы;
* необязательная колонка `Маркетплейс` (или строка-маркер `ozon` / `yandex` внутри
  файла) делит файл на два списка — получите два PDF;
* листов может быть несколько — берётся тот, где нашлись артикулы;
* бот отвечает, что именно распознал («колонка артикулов «Ваш SKU», количество «Кол-во»»),
  чтобы можно было проверить глазами.

Готовый шаблон — команда `/template`. Выгрузки Ozon (`.csv`) и Yandex (`.xlsx`)
читаются этим же разбором, отдельно настраивать ничего не нужно.

Ограничение Telegram: боту отдаются файлы не больше 20 МБ. Пул из ~60 этикеток
весит около 9 МБ, так что в лимит укладывается; очень большой архив лучше
прислать файлами или разбить.

## Результат

Для каждого списка — отдельный PDF `<МАРКЕТПЛЕЙС>_<ПУЛ>_CZ_po_spisku.pdf`,
документом в чат (копия в `~/.cz_bot_pools/<chat_id>/_out/`). Итог одной строкой:

```
ozon 40/40, yandex 9/9.
```

Если что-то не сошлось — причина следующей строкой:

```
ozon 29/31, yandex 8/8.
не найдено в папке FIZ 29: SOCKS-FIZ001 (нужно 2 шт, файла нет вообще).
```

Отдельно предупреждается случай, когда в списке позиций больше, чем страниц
в этикетке: страница дублируется, но один и тот же код ЧЗ нельзя наклеить
на два товара — это надо увидеть до печати.

```
не хватило страниц: FL-SHRT002H-XL (нужно 2, в файле 1) — последняя страница
продублирована, проверьте перед печатью.
```


## Файлы

| файл | назначение |
|---|---|
| `app/tg_bot.py` | бот: хендлеры, доступ, отчёты |
| `app/message_parser.py` | разбор свободного текста сообщения |
| `app/pool.py` | пул: склейка этикеток в один PDF, индекс внутри файла, распаковка zip |
| `app/pool_store.py` | хранилище пулов и накопитель входящих файлов |
| `app/folders.py` | запасной режим: поиск папки на диске по короткому имени |
| `app/matcher.py` | матчинг «артикул → файл» (точное + 2 фолбэка), парсинг выгрузок |
| `app/pdf_io.py` | чтение PDF с повторами (`Errno 35 Resource deadlock avoided`) |
| `app/pdf_builder.py` | сборка PDF с курсором страниц по артикулу |
| `app/main.py` | десктопный GUI на той же логике (`./run.sh`) |
